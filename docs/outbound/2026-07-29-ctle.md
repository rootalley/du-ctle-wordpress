## One thing to be careful about — please don't push staging to live

Amanda, I've sent you a separate note on this, but Persis should see it too since it affects how work reaches the live site.

**Please don't use the "Push to Live" button in MyKinsta.** If something built in staging needs to reach the live site, send it to me and I'll move it across.

The reason is that our setup is unusual, and not in a way anyone would guess. Normally you build in staging and push to live — that's correct practice nearly everywhere, and it's what Kinsta's interface is designed around. We did the reverse on purpose: Microsoft Entra single sign-on is tied to a specific web address, so building it in staging would have meant asking DU IT to register two of them instead of one. So all the security and infrastructure work went directly onto the live site, *after* the staging copy was made.

That means the live site now holds a great deal that staging has never seen. A push from staging wouldn't add work to the live site — it would replace the live site with an older copy and take the security setup with it. There's also a wrinkle in how Kinsta handles this: even a careful, narrow push still carries a few server settings across, so there's no version of it that's fully safe here.

I'll sort out a proper way to move staging work onto the live site, and I'll come to Amanda to get the details right. Nothing is broken and nothing has been lost — I caught this while reviewing, not because anything went wrong.
- **Updated PHP to version 8.4.** Amanda, this is the one that might matter to you: no visible change to the site, but if you have version-specific code in flight, this is your heads-up. It's reversible if it causes trouble.
- **The login page has moved off the standard WordPress URL** as a security measure. **You cannot log in without the new address — I'm sending it to each of you individually, not in this email.**
